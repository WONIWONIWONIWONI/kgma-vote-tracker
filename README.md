# KGMA TOP 2 — VOTE/TRACK

2026 KGMA Berriz 공개 투표 화면의 상위 2팀을 기록하고 시각화합니다.

## 현재 확인된 상태

- 현재 기록은 자동 수집으로 확인한 값만 포함하며 **2026-10-07 00:45 KST**부터 시작합니다. 사용자 캡처로 추가했던 기록은 삭제했습니다.
- **GitHub Actions에서 실제 공개 페이지 수집과 기록 저장을 확인했습니다.** 첫 성공은 2026-10-07 00:51 KST이며, 원본 집계 시각 00:45 KST의 RESCENE 3,506표, RIIZE 3,091표를 저장했습니다. 작업 환경과 달리 GitHub 실행 환경에서 원본에 정상 접속했습니다.
- 확인되지 않은 과거 데이터는 포함하지 않았습니다. 저장 데이터에는 관측값만 포함하고, 그래프에서는 미관측 구간의 앞뒤 관측점을 직선으로 연결합니다.

## 화면 열기

`dist/index.html`은 최근 기록 사본을 먼저 표시합니다. 공개 웹사이트에서는 최초 접속 때 `history.json` 전체 기록을 한 번 가져온 뒤, 5분마다 최근 3개 관측만 담긴 `latest.json`을 읽고 기존 기록에 합칩니다. 오래 자리를 비워 중간 기록이 없는 경우에만 전체 파일을 다시 가져옵니다. 연결 실패 시 이미 확인한 기록을 보존합니다. **페이지 새로고침과 데이터 수집은 별개입니다.** 현재 운영 중인 GitHub Actions가 방문자 유무와 관계없이 기록을 저장합니다. 매번 사이트를 다시 배포할 필요 없이 최신 기록이 반영됩니다. 사용자의 컴퓨터나 ChatGPT를 켜 둘 필요가 없습니다.

## 공개 운영 — GitHub Pages + Actions

1. 이 프로젝트를 새 공개 GitHub 저장소의 `main` 브랜치에 올립니다. `.github/workflows` 폴더도 포함합니다.
2. 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 설정합니다.
3. Actions → **Collect KGMA votes continuously**와 **Publish KGMA dashboard**를 각각 한 번 실행합니다. 관련 코드 변경 시에는 자동 실행됩니다.
4. 수집 성공 로그의 `sourceAt`과 공식 페이지를 비교합니다. 수집 실패 시에도 마지막으로 검증된 기록과 오류 상태를 저장합니다. 과거 값을 0이나 가짜 값으로 바꾸지 않습니다.
5. 게시 작업에 표시되는 `https://사용자명.github.io/저장소명/` 주소를 공유합니다.

수집 작업 하나가 최대 **5시간 30분** 동안 실행되며, 시작 직후 한 번 확인한 다음 매 5분 경계에서 120초 뒤(예: 02:02:00, 02:07:00, 02:12:00)에 공개 순위 API를 읽습니다. 기대한 새 집계가 아직 없으면 20초 간격으로 해당 구간의 04분·09분 지점까지 재확인합니다. 새 집계가 확인되면 다음 정상 주기까지 기다립니다. 수집에 걸리는 시간을 다음 간격에 더하지 않아 주기가 계속 밀리지 않습니다. 각 회차는 원본 조회 후 검증된 기록과 상태를 즉시 커밋합니다.

예약식 `7,22,37,52 * * * *`는 다음 실행을 미리 대기시키는 용도입니다. 같은 동시 실행 그룹에서 수집기는 하나만 실행되고, 새 예약은 대기 중인 작업만 교체합니다. 수집 코드 변경으로 인한 push는 기존 실행을 취소하고 새 코드로 교대합니다. 현재 작업이 끝나면 대기 작업이 최신 `main`을 받아 이어받습니다. 한 번 실패해도 다음 주기에 다시 시도하고, 세 번 연속 실패하면 현재 작업을 종료해 대기 작업이 새 환경에서 재시작하도록 합니다.

이 방식은 매 수집마다 GitHub 예약 실행을 기다릴 때 생기던 공백을 줄입니다. **목표는 원본에 공개된 새 집계를 정상 운영 시 5분 이내에 표시하는 것입니다. GitHub 실행 대기·장애, 작업 교대, 원본 갱신 지연까지 포함한 절대적인 5분 상한은 보장할 수 없습니다.** 실제 원본 집계 시각을 그래프의 x축에 사용합니다.

화면 배포는 코드 변경 또는 수동 실행 때만 합니다. 배포 전에 Chromium으로 320·360·390·430·768·1280px에서 카드 크기, 가로 넘침, 큰 표수, 기록 접기/펼치기를 검사합니다. 주기적인 재배포는 없습니다. 최신 기록은 배포를 기다리지 않습니다. 두 워크플로 모두 공개 저장소와 표준 `ubuntu-latest`만 사용합니다. 배포 파일은 전체 10MiB 이하인지 검사하고, 배포 성공 직후 해당 임시 아티팩트를 삭제합니다. 삭제 실패 시에도 1일 보관 기간으로 만료됩니다.

운영 기간은 첫 관측 기준 **2026-10-07 00:45 ~ 2026-10-21 00:45 KST**입니다. 종료일은 투표의 공식 종료일을 의미하지 않고 이 트래커의 2주 운영 한도입니다. `collector/policy.py`에 고정된 종료 시각이 있으며, `COLLECT_UNTIL` 변수로 더 일찍 끝낼 수 있습니다. 실수로 더 늦은 변수를 입력해도 고정된 종료일을 넘기지 않습니다.

종료 시각에는 원본 요청 없이 종료 상태를 저장하고 수집 워크플로의 향후 예약을 비활성화합니다. 이미 대기 중인 실행이 시작되어도 종료 여부를 먼저 검사해 원본 수집을 건너뜁니다. 수집기는 브라우저를 설치하지 않고 Python 기본 라이브러리로 공개 API를 읽습니다. 사이트와 기록은 읽기용으로 남고, 브라우저의 자동 새로고침도 종료됩니다.

## 2주 무료 운영 설계

- **화면 요청:** 기본 확인 시각은 02분 25초·07분 25초 등입니다. 아직 이전 집계이면 해당 구간의 04분 30초·09분 30초까지 20초 간격으로 작은 최근 기록 파일만 재확인합니다. 숨겨진 탭에서는 확인을 쉬고, 탭으로 돌아오면 필요할 때 다시 확인합니다. 수동 새로고침도 가능합니다.
- **전송량:** 전체 기록은 처음 한 번, 이후에는 최근 3건만 전송합니다. 오래된 응답이 다음 주기까지 남지 않도록 최신 파일 요청에는 새 쿼리와 no-store를 사용합니다. 이 변경은 반영 속도를 위해 적용하며, 새 집계 대기 중에는 요청 수가 늘어납니다.
- **기록 저장:** JSON 공백을 줄이고 동일 원본 시각·수치의 중복 확인은 파일과 커밋을 추가하지 않습니다. 원본이 정체되면 마지막 관측 시각으로 지연을 표시합니다. 새 관측 없이 오류에서 복구되는 경우에는 상태만 갱신합니다.
- **크기 제한:** 관측은 4,100개, 전체 JSON은 8MiB, 배포 파일 합계는 10MiB를 넘으면 작업을 멈춥니다. 이전 정상 기록을 잘라내거나 삭제하지 않습니다.
- **프로그램 캐시:** 수집기는 별도 패키지나 브라우저 캐시를 사용하지 않습니다. 화면 변경 시의 브라우저 검사에만 Playwright 1.63.0을 사용합니다. 실행별·날짜별 캐시 키를 생성하지 않습니다. 두 기존 캐시의 최근 확인 크기는 49,000,507 + 284,184,242바이트(약 318MiB)이며, 버전 고정으로 바뀐 새 키와 잠시 공존하더라도 10GiB보다 작게 유지될 것으로 예상합니다. 계정 전체 캐시·청구 현황을 조회한 값은 아닙니다.
- **임시 저장:** 진단 파일을 아티팩트로 올리지 않고 정기 배포를 하지 않습니다. 성공한 배포 아티팩트는 삭제하고 실패 시에는 1일 뒤 만료합니다.
- **종료:** 2주 뒤 원본 조회·반복 작업·브라우저 자동 확인을 종료합니다.

현재 팀 이름과 수치 자릿수를 늘린 **4,032개 관측의 크기 시험**에서는 전체 JSON 약 1.57MB, 최근 3건 약 1.5KB였습니다. 기본 5분 확인만 계산하면 한 탭의 14일 반복 데이터 본문은 약 6MB 수준입니다. 원본 반영을 기다리는 짧은 재확인, 최초 전체 다운로드, HTTP 헤더, 수동 새로고침은 별도입니다. 이는 저장량을 가늠하는 시험값이고 예상 득표수나 방문자 수를 뜻하지 않습니다.

공개 저장소의 표준 Actions 실행 시간에는 비공개 저장소용 월 2,000분 한도가 적용되지 않습니다. 아티팩트/Packages 공유 무료 저장은 500MB, 캐시는 별도 저장소당 기본 10GB입니다. Pages는 사이트 1GB, 월 100GB의 소프트 전송 한도가 있습니다. 데이터 JSON은 GitHub의 공개 raw 파일에서 받아 Pages의 화면 배포와 분리되며 별도의 서비스 요청 제한이 적용될 수 있습니다. 방문자 수가 알려져 있지 않으므로 무제한 트래픽이나 무중단 운영을 보장하지 않습니다.

이 구성은 유료 실행기·서버·AI API·LFS를 사용하지 않습니다. **결제수단을 등록하지 않은 계정은 무료 한도 소진 시 유료 사용이 차단된다**는 GitHub 안내가 별도로 적용됩니다. 다른 저장소/구독의 사용량과 계정 결제 설정은 이 프로젝트의 코드로 통제하지 않습니다.

## 상시 실행 수집기

Python 3.10 이상 환경에서:

```sh
python collector/collect.py --every 300
```

이 모드는 실행한 컴퓨터가 켜져 있어야 합니다. 로컬 `dist/data` 파일을 갱신하며 GitHub에 자동 전송하지 않습니다. 웹 서버가 같은 `dist` 폴더를 제공하는 경우 바로 반영됩니다. GitHub Pages 운영은 Actions 방식을 사용하세요.

계정이나 비밀번호는 사용하지 않습니다. 베리즈 페이지가 사용하는 공개 조회 API `https://svc-api.berriz.in/service/v1/votes/2026kgma/stats`를 읽습니다. 로그인·인증·접속 제한이 나타나면 오류를 표시하며 우회하지 않습니다. API의 집계 시각과 화면의 실제 수집 시각은 다를 수 있습니다.

## 데이터 처리

- **1·2위 전용 스키마:** `schemaVersion: 2`, 각 관측의 `top2`에 두 팀만 저장합니다. 기존 `top3` 기록은 3위 항목만 제거하고 집계 시각·최초 수집 시각·총투표수·1·2위 값은 그대로 보존합니다. 앞으로도 각 관측 시점의 1·2위만 저장합니다.
- **시간대별 증가량:** 한국 시간의 정시부터 다음 정시까지 같은 팀 ID의 누적 표수 차이를 계산합니다. 내부 관측이 빠져도 두 정시가 있으면 정확한 한 시간 증가량을 얻을 수 있습니다. 정시가 없으면 그 시간 안에 실제로 있는 두 관측의 차이만 `일부 구간`으로 표시하고 실제 비교 시각을 명시합니다. 경계를 넘긴 누락 구간을 임의로 나누지 않습니다. 비교 관측이 부족하면 0 대신 —로 표시합니다.
- 시간대별 화면은 날짜 선택, 두 팀의 가로 막대와 정확한 표수, 집계 중/완전한 1시간/일부 구간 상태를 제공합니다. 기본 최근 6개 시간이며 나머지는 더 보기와 내부 스크롤로 확인합니다. 해당 날짜의 모든 막대는 동일한 눈금입니다. 새로 수집하거나 별도 요청하지 않고 이미 받은 기록으로 계산합니다.

- 점유율: 팀 득표수 ÷ 전체 투표수 × 100. 카드에는 원본 표시 비율, 그래프와 증감에는 정확한 계산값을 사용합니다.
- 득표수·점유율 그래프: 최신 상위 2팀의 팀별 기록. 과거에 상위 2위 밖이었다면 값이 없습니다.
- 표차 그래프: 각 시점의 순위끼리 비교합니다. 순위가 바뀌면 그 순위를 차지하는 팀도 바뀝니다.
- 직전 관측 대비 변화: 가장 최근 관측과 바로 직전 관측의 표수·점유율을 같은 팀 ID로 비교합니다. 실제 관측 간격과 비교 시각을 표시하며, 직전 상위 2위 밖이던 팀은 —로 표시합니다.
- 모바일: 같은 너비와 높이의 순위 카드, 카드 밖으로 넘치지 않는 표. 집계 기록은 기본 접힘이며 펼친 뒤에도 표 내부에서 스크롤합니다.
- 화면 그래프와 PNG: 관측점 사이의 미관측 구간도 직선 연결합니다. 실제 관측점에만 점·툴팁이 있으며 CSV에 가상 관측값을 추가하지 않습니다.
- 같은 원본 시각은 중복 기록하지 않습니다. 같은 시각에 서로 다른 수치가 들어오면 검토할 수 있도록 오류를 표시합니다.
- 오래되거나 읽기에 실패한 값은 정상 갱신으로 표시하지 않습니다.
- 방문자는 공통 기록을 보기만 하며 데이터를 수정할 수 없습니다.

## 파일

- `dist/`: 외부 빌드 도구 없이 동작하는 1·2위 전용 정적 웹사이트.
- `dist/hourly.js`, `qa/test_hourly.cjs`: 관측 기준 시간별 증가량과 정시·누락·순위 변경·KST 계산 검증.
- `collector/collect.py`: 공개 API 조회, 표수·비율 검증, 시간별 기록 보존.
- `collector/runner.py`: 고정 5분 시계와 기록 커밋, 제한 시간 종료.
- `collector/policy.py`, `collector/lifecycle.py`: 2주 운영 한도와 예약 비활성화.
- `collector/prepare_site.py`: 작은 초기 사본과 배포 크기 제한.
- `.github/workflows/collect-and-publish.yml`: 연속 수집과 다음 실행 대기.
- `.github/workflows/publish.yml`: 코드 변경 시 Pages 배포와 임시 파일 정리.

## 수집 중지와 사이트 종료

- **수집만 중지:** 저장소 Actions → Collect KGMA votes continuously → 우측 `…` → Disable workflow. **실행 중인 작업과 대기 중인 작업도 각각 Cancel workflow로 취소**합니다. 이미 시작한 작업은 비활성화만으로 종료되지 않습니다. 대기 작업 시작까지 막으려면 Actions Variables에 `COLLECT_ENABLED=false`도 설정할 수 있습니다. 기존 사이트와 기록은 남습니다.
- **웹사이트도 내리기:** 먼저 수집을 중지하고 Publish KGMA dashboard도 Disable workflow로 비활성화한 다음 Settings → Pages → Source를 Deploy from a branch로 변경 → Branch를 None으로 선택 → Save. 저장소의 코드와 기록은 남습니다.
- **저장소까지 삭제:** Settings → General → Danger Zone → Delete this repository. 이 프로젝트의 코드·수집 기록·사이트가 함께 삭제되므로 보관할 자료가 있으면 먼저 내려받습니다.

현재 구성은 공개 저장소의 표준 `ubuntu-latest` 실행 환경과 GitHub Pages를 사용합니다. 표준 실행 시간과 Pages 호스팅은 무료로 이용할 수 있습니다. 별도 유료 서버나 AI API를 사용하지 않습니다. 저장 공간·캐시의 무료 한도와 유료 설정 변경은 별도 조건을 따릅니다.
